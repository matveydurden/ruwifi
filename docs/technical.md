# RU напрямую

Нативное приложение macOS с одним переключателем и постоянной фоновой службой. При включении новые соединения к `.ru`, `.рус`, `.рф`, `1cfresh.com` и их поддоменам идут через Wi-Fi. Основной маршрут остаётся под управлением существующего VPN.

## Использование

1. Откройте `RU напрямую.app` и нажмите «Установить и включить».
2. Подтвердите системный запрос macOS — пароль в Terminal не требуется. Приложение установится в `/Applications`, фоновая служба — в launchd.
3. Дождитесь статуса «Работает». После первой установки один раз перезапустите Chrome: соединения, открытые до установки, не переносятся между сетями. При последующих переключениях уже открытые соединения сторонних программ также могут потребовать переподключения.
4. Кнопка «Выключить» возвращает прежние параметры DNS macOS и Chrome. VPN продолжает работать самостоятельно.

Служба запускается при загрузке Mac и сохраняет выбранное состояние. Интерфейс запускается при входе пользователя; закрытие окна не выключает службу. Если выключить режим, после перезагрузки он останется выключенным.

## Границы поведения

- Правило относится к DNS-именам с окончанием `.ru`, `.рус` (`xn--p1acf`) и `.рф` (`xn--p1ai`), включая произвольное число поддоменов. Дополнительное исключение — `1cfresh.com` вместе со всеми поддоменами. `.ru.com`, иностранные IDN-зоны, остальные домены и ресурсы сайта на `.net`/`.com` не входят в прямой маршрут.
- Поддерживаются системный DNS macOS и Chrome с параметрами DNS, которые служба применяет на время работы. Произвольное приложение со своим скрытым DNS, встроенным прокси/VPN или ранее сохранённым реальным IP может обойти доменную классификацию.
- Потеря Wi-Fi не включает VPN как запасной выход для распознанных `.ru`, `.рус`, `.рф` и `1cfresh.com`. IPv6-only сайты недоступны, если прямое подключение Wi-Fi не поддерживает необходимый адресный протокол. Эта версия разрешает прямые назначения по IPv4.
- Сервис не подключает и не отключает VPN-клиент и не заменяет его Kill Switch. Если сам VPN отключён, обычный трафик следует системным маршрутам; интерфейс показывает это состояние отдельно.
- Выключенный режим оставляет небольшой движок для обработки уже закэшированных виртуальных адресов по обычному маршруту. Это предотвращает поломку вкладок при переключении.
- Chrome может показывать управление настройками: служба временно задаёт только `DnsOverHttpsMode` и `BuiltInDnsClientEnabled`. Исходный файл сохраняется. Внешние изменения не перезаписываются молча.

## Устройство и восстановление

Локальный DNS выдаёт для `.ru`, `.рус`, `.рф` и `1cfresh.com` отдельные FakeIP-адреса. TUN захватывает только `198.19.0.0/16` и `fd7a:7275:7769::/48`, без второго default route. Прямой выход привязан к аппаратному Wi-Fi. DNS к upstream Cloudflare передаётся по HTTPS. Более широкие reject-маршруты блокируют виртуальные адреса при падении движка. Движок контролируется отдельной launchd job; при загрузке Mac служба сначала создаёт защитные маршруты и только затем запускает движок.

macOS использует отдельные resolver-файлы в `/private/etc/resolver/`: `ru`, `1cfresh.com`, `xn--p1acf` и `xn--p1ai`. DNS-правила и маршруты используют эти же ASCII-имена, поэтому кириллические домены не требуют отдельных списков сайтов. Общий resolver для `.com` или всех IDN-зон не создаётся. Каждый файл имеет журнал исходных данных: прежний `resolver-journal.json` для `.ru` сохраняется при обновлении, для остальных используется `resolver-<суффикс>-journal.json`. Выключение восстанавливает все четыре файла; ошибка одного восстановления не мешает попытке восстановить остальные. Установщик включает все файлы и журналы в снимок отката.

Настройки и кэш службы: `/Library/Application Support/RUWiFi`.
Пользовательское состояние: `~/Library/Application Support/RUWiFi/preferences.json`.
Автозапуск службы: `/Library/LaunchDaemons/local.matvey.RUWiFi.Service.plist`.
Необязательная миграция для пользователей раннего прототипа: при наличии известной старой службы `com.codex.eis-split-tunnel` установщик проверяет точный хеш её скрипта и параметры launchd, затем отключает её и удаляет только маршруты из её журнала, совпадающие с текущим Wi-Fi. Её скрипт и plist сохраняются; снимок удалённых маршрутов записывается в `legacy-retired.json`. Неизвестная версия старой службы останавливает автоматический перенос с ошибкой.

Автозапуск интерфейса: `~/Library/LaunchAgents/local.matvey.RUWiFi.Login.plist`.

Окно проверяет опубликованный статус каждые 250 мс, в том числе пока открыто меню. Пользовательская блокировка `interface.lock` допускает один экземпляр интерфейса; повторное открытие показывает уже запущенное окно, а фоновый повторный запуск завершается. Блокировка освобождается при выходе процесса. Повторное открытие ждёт подтверждения окна до двух секунд; если первый интерфейс занят или не отвечает, приложение предлагает повторить открытие. Скорость применения маршрутов зависит от отдельной службы и её сетевых проверок.

Интерфейс читает поколение настроек, время последней проверки и хеш установленной службы. Применение DNS выполняется только после готовности движка. Журнал восстановления записывается до изменения файлов. Чужие изменения и символические ссылки приводят к ошибке вместо перезаписи.

Статус службы проверяет только локальный DNS на `127.0.0.1:15453` и таблицу маршрутов FakeIP. Служба не делает HTTP-запросов к Яндексу или другим внешним сайтам для диагностики. Статус «Работает» подтверждает локальную готовность, а не доступность интернета. Обычный трафик пользователя и его DNS-запросы продолжают обрабатываться штатно.

Терминальный установщик проверяет архив до запроса прав и вызывает стандартное окно macOS через AppleScript. Отмена или ошибка подтверждения останавливает установку; успешное сообщение и завершение настройки выполняются только после успешного выхода helper. Подтверждение необходимо для системной службы, но не для последующих переключений. Полный сценарий с реальным вводом пароля проверяется отдельно от автоматических тестов.

## Сборка и проверки

Из корня репозитория: `./app/build.sh`. Скрипт использует Swift Command Line Tools, Python 3 и Go. Исходники движка находятся в `vendor/sing-box`: версия 1.14.2 (коммит `af6e64c3b69e6132ebaee0e1a3d24e93903f6709`) с исправлением устойчивости FakeIP-кэша к аварийному завершению. Курсор выделения адресов сохраняется синхронно перед выдачей адреса; при старте метаданные не удаляются. Сборка движка помечена `1.14.2-ruwifi.1`; лицензия GPLv3 приложена.

`CoreTests.swift`: распознавание VPN без привязки к провайдеру, границы доменов, изоляция маршрутов, начальный маршрут при восстановлении, переключение, актуальность статуса.
`InterfaceRuntimeTests.swift`: обновление статуса в обычном режиме и при открытом меню, единственный экземпляр интерфейса, повторное открытие при выходе предыдущего экземпляра.
`InstallTests.swift`: первая установка, сохранение выключенного состояния при обновлении, автозапуск интерфейса.
`StorageTests.swift`: безопасное чтение, атомарная запись, восстановление, внешние изменения и права файлов.
`DomainResolverTests.swift`: все четыре resolver-файла, добавление кириллических зон при обновлении с сохранением журнала `.ru`, повторное включение, восстановление ранее существовавших настроек и прав, откат, внешние изменения и символические ссылки.
`RoutingHealthTests.swift`: готовность без внешнего интернета, отказ при неверном локальном DNS, неверном маршруте или ошибке локальной команды.
`integration_test.py`: настоящий движок в отдельном процессе без системного TUN; локальные DNS и HTTP-фикстуры, границы `.ru`, `.рус`, `.рф` и `1cfresh.com`, вложенные имена, отсутствие обходящих IP-подсказок HTTPS, переключение выхода, перезапуск, аварийное завершение с сохранением FakeIP и отказ без запасного выхода при недоступном исходящем соединении. Внешние сайты не используются, временные процессы завершаются.

После установки локально проверяются версия, состояние службы, DNS FakeIP, маршруты и автозапуск. Проверки внешнего выхода и браузеров в установку не входят и выполняются только по отдельному запросу пользователя. Модульные тесты не подтверждают физический сон или перезагрузку ноутбука.
